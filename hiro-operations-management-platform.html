Project scope

A backend-led operations platform connecting daily business workflows.

The platform centralizes internal operations for a technical hardware/software company. It connects customer identity, GNSS/device records, manufacturing data, assignments, releases, inventory, repair flows, NTRIP checker sessions, post-process jobs, operational statistics, and system-health signals.

The dashboard is the visible command layer. Behind it is a broad ASP.NET Core backend with domain-specific APIs, SQL Server-backed workflows, repository implementations, DTO contracts, authorization rules, and admin-facing operations.

01 Operational backbone

Connects users, devices, manufacturing, inventory, repair, releases, and service monitoring.

02 Command-layer dashboard

Turns backend signals into admin-facing KPIs, action items, charts, and health indicators.

03 Domain-driven structure

Separates workflows into maintainable modules with clear API, service, data, and UI boundaries.

Architecture

Backend architecture designed around workflows, security, and data access.

The backend separates HTTP boundaries, authorization, application commands and queries, service logic, domain contracts, repository access, and infrastructure integrations. This keeps operational workflows maintainable as the platform grows across users, devices, manufacturing, commerce, RMA, NTRIP, releases, and dashboard reporting.

Request lifecycle

Request lifecycle from client action to response contract

Domain requests pass through explicit HTTP, security, application, service, repository, and data boundaries before returning stable response contracts to admin and client applications.

01 Client Applications

Next.js admin dashboard, Android app, and device/service clients.

02 ASP.NET Core API

Controllers expose domain-based REST endpoints and enforce HTTP boundaries.

03 Authentication & Authorization

JWT, RBAC, policies, session validation, identity verification, and device ownership checks.

04 MediatR Command / Query

Commands and queries route operations outside controller logic.

05 Application Services & Validators

Handlers, services, validators, and DTO mapping coordinate workflow logic.

06 Dapper Repository

Repositories execute SQL Server queries and operational reporting reads.

07 SQL Server / Redis

SQL Server stores operational data; Redis supports cache/session-related services.

08 Response DTO → Admin UI

Stable response contracts power KPIs, workflows, charts, and admin views.

Security, data and operations

Security, data access, and operational reliability.

Sensitive operations are handled through backend rules, not UI assumptions. Authorization policies, identity checks, device ownership validation, SQL-backed workflows, background processing, and dashboard aggregation work together to protect operational data and keep admin workflows consistent.

Access model

Backend-enforced access model

Admin actions, customer data, device operations, identity review, RMA workflows, NTRIP sessions, and dashboard statistics are protected through backend authorization rules, not just frontend visibility.

01JWT / RBACAuthenticated user and role context
02Policy checksEndpoint-level permission rules
03Session validationActive session and access consistency
04Identity verificationVerified user state for sensitive flows
05Device ownershipCustomer-device access control
06Authorized actionAllowed workflow execution
Security boundary

Role-based access

JWT, RBAC, policy authorization, admin roles, and permission-controlled actions protect sensitive operational endpoints.

Ownership boundary

Identity and ownership checks

Identity verification status, document review, session validation, endpoint access, and device ownership rules control who can operate which records.

Data boundary

Operational data access

Dapper repositories, SQL Server queries, migrations, reporting queries, and DTO mapping keep persistence logic separated from API and UI layers.

Workflow boundary

Workflow reliability

Post-process job states, failed-job detection, release workflows, RMA timelines, payment states, and freshness checks support operational consistency.

Visibility boundary

Dashboard aggregation

Statistics APIs aggregate signals from users, devices, commerce, RMA, NTRIP, releases, events, and system health into admin-facing summaries.

Public case study

Privacy-aware public presentation

Sensitive values such as phone numbers, national IDs, serials, tracking codes, GUIDs, and precise positions are masked or removed for portfolio presentation.

Why this matters

Operational dashboards can expose sensitive actions. This platform keeps those actions behind backend policies, verified identity states, ownership checks, and controlled data contracts.
